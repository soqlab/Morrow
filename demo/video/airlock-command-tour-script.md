# Airlock Command tour — narration script

The words burned into `airlock-command-tour.mp4`, in order. Timings are
for the delivered cut. There is no voice-over in the delivered file;
these are the words to read if you want one.

Generated by `assemble-tour.py` from the cut it builds, so it cannot
drift from the picture.

## Opening

**0:07**  Everything here is a live build reading a seeded database. The customer is Example Financial Group — an invented bank.


## 1. The problem in plain words

**0:24**  Traffic your organisation encrypts today can be recorded today.

**0:30**  It becomes readable later, once a quantum computer can break RSA and elliptic-curve cryptography.

**0:38**  So data with a long secrecy requirement is already exposed — though nothing has been broken yet.

**0:46**  The console opens on posture: inventory, open fixes, modelled exposure and crypto-agility.

**0:54**  And the deadlines are not hypothetical. CNSA 2.0, NSM-10 and NIST guidance carry published dates.

**1:02**  Optimistic, median and conservative scenarios — not one confident date.

**1:09**  Some target dates have already passed. Others land in 2030 and 2033.

**1:16**  The platform models when a relevant quantum computer becomes credible — and labels it as a model.


## 2. Discovery

**1:31**  Airlock Command scans TLS endpoints and records what each one really negotiated.

**1:38**  Protocol version, cipher suite, key algorithm, key size, and the certificate chain behind it.

**1:46**  Eight scan runs over five months, so the history has shape rather than being one snapshot.

**1:54**  The inventory it builds. Thirty-eight endpoints, every one with an owner beside it.

**2:01**  Each endpoint carries an owner, a team, an environment and a data-confidentiality lifetime.

**2:09**  RSA 2048 and 3072. Elliptic curve P-256 and P-384. One gateway already negotiating a hybrid key exchange.

**2:18**  Confidentiality lifetime is the field that matters most — how long this data has to stay secret.

**2:26**  Ownership is what turns a cryptographic finding into work a named team can be asked to do.


## 3. Exposure

**2:40**  It is what an adversary could store today and read after Q-Day.

**2:46**  So each asset is priced: what the traffic is worth, how long it stays secret, the odds it is broken by then.

**2:55**  Exposure grouped by algorithm class. RSA-2048 carries most of it.

**3:02**  The priority queue is ranked by modelled exposure, not by a severity label.

**3:09**  Owner, environment, algorithm, probability broken, data category, and how long it has been harvestable.

**3:17**  Then the exposure timeline.

**3:22**  It is a real three-dimensional chart. You can turn it.

**3:29**  Amber is traffic captured but still sealed.

**3:34**  Red is the same traffic, readable, once the model's Q-Day wall is crossed.

**3:40**  Beside it, the probability ribbons: one curve per algorithm, with the year each reaches a fifty per cent chance.

**3:50**  Every modelled figure carries a badge saying it is a model, with the date, the sources and the assumptions.

**3:59**  Nothing here is presented as measurement when it is an estimate.


## 4. Evidence

**4:11**  The cryptographic bill of materials is generated from the scans themselves, in CycloneDX 1.6.

**4:19**  Every protocol, certificate and algorithm found, each with its quantum status.

**4:26**  Eighty-seven components in this estate. Two of them are already post-quantum.

**4:33**  Downloadable as JSON or CSV, so it can leave the product and still mean something.

**4:41**  Then the mapping to control frameworks. It is honest: this estate scores badly, and it says so.

**4:49**  Evidence packs collect the control artefacts with timestamps and a hash chain.


## 5. Action

**5:02**  Every fix moves through suggested, approved, pull request, and verified closed.

**5:10**  Two are closed and verified against a later scan. Seven are still open.

**5:16**  Open one and it carries the file, the current configuration, and the proposed change.

**5:24**  Approve, reject, validate, open a pull request, mark merged — every step is recorded against the asset.

**5:33**  Before you change a certificate authority, you want to know what depends on it.

**5:40**  Assets, repositories and fixes in one graph you can interrogate.

**5:47**  Two roots and two issuing authorities sit under thirty-eight leaf certificates here.

**5:54**  If that public root failed, the dependent nodes beneath it would be affected — and the model prices it.

**6:03**  And a tripwire ladder: five canary keys at five strengths. Each only breaks if that algorithm breaks.

**6:11**  So the first one to trip tells you how far quantum capability has actually reached.


## 6. Governance

**6:54**  The executive view is the same view the engineers work in. There is no second set of numbers.


## 7. For the buyer's security team

**7:09**  One: tenant isolation is enforced in the database, not only in application code.

**7:16**  Row-level security, scoped per organisation, with a cross-tenant probe you can run yourself.

**7:24**  Two: vendor support cannot look at your workspace silently. Read-only, time-limited, with a stated reason.

**7:33**  Three: the audit trail is hash-chained, so a removed entry is detectable.

**7:40**  Four: the operators who run the platform sign in through an identity provider, with authenticator MFA.

**7:49**  Destructive actions ask for a fresh code. The shared key is an emergency credential only.

**7:56**  And the data boundary is explicit about what is allowed to leave your environment.

**8:04**  Cryptographic metadata, fingerprints and workflow records may cross. Source code, private keys and tokens do not.
