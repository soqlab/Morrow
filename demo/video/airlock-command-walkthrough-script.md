## Opening

**0:00**  Airlock Command

**0:05**  A cryptographic governance platform for the post-quantum migration.

**0:12**  Recorded against a live build and a fictional customer estate.


## 1. The problem in plain words

**0:20**  Traffic your organisation encrypts today can be recorded today.

**0:27**  It becomes readable later, once a quantum computer can break RSA and elliptic-curve cryptography.

**0:38**  So data with a long secrecy requirement is already exposed, though nothing has been broken yet.

**0:48**  The company here is Example Financial Group — an invented bank with thirty-eight endpoints.

**0:57**  The console opens on posture: inventory, open fixes, modelled exposure and crypto-agility.

**1:07**  And the deadlines are not hypothetical. CNSA 2.0, NSM-10 and NIST guidance carry published dates.

**1:16**  Optimistic, median and conservative scenarios — not one confident date.

**1:23**  Some target dates have already passed. Others land in 2030 and 2033.

**1:29**  The platform models when a relevant quantum computer becomes credible — and labels it as a model.


## 2. Discovery

**1:40**  Discovery.

**1:45**  Everything downstream starts with what you actually run, not what the documentation says you run.

**1:55**  Airlock Command scans TLS endpoints and records what each one really negotiated.

**2:03**  Protocol version, cipher suite, key algorithm, key size, and the certificate chain behind it.

**2:11**  Eight scan runs over five months, so the history has shape rather than being one snapshot.

**2:20**  The inventory it builds.

**2:24**  Each endpoint becomes an asset with an owner, a team, an environment and a data-confidentiality lifetime.

**2:35**  RSA 2048 and 3072. Elliptic curve P-256 and P-384. One gateway already negotiating a hybrid key exchange.

**2:44**  Confidentiality lifetime is the field that matters most — how long this data has to stay secret.

**2:53**  Ownership is what turns a cryptographic finding into work a named team can be asked to do.


## 3. Exposure

**3:03**  Exposure.

**3:07**  Harvest now, decrypt later. The question is not whether an endpoint is weak today.

**3:16**  It is what an adversary could store today and read after Q-Day.

**3:23**  So each asset is priced: what the traffic is worth, how long it stays secret, the odds it is broken by then.

**3:35**  Exposure grouped by algorithm class. RSA-2048 carries most of it.

**3:42**  The priority queue is ranked by modelled exposure, not by a severity label.

**3:49**  Owner, environment, algorithm, probability broken, data category, and how long it has been harvestable.

**3:59**  Then the exposure timeline.

**4:02**  It is a real three-dimensional chart. You can turn it.

**4:08**  Amber is traffic captured but still sealed.

**4:14**  Red is the same traffic, readable, once the model's Q-Day wall is crossed.

**4:22**  Beside it, the probability ribbons: one curve per algorithm, with the year each reaches a fifty per cent chance.

**4:32**  Every modelled figure carries a badge saying it is a model, with the date, the sources and the assumptions.

**4:43**  Nothing here is presented as measurement when it is an estimate.


## 4. Evidence

**4:51**  Evidence.

**4:55**  Exposure is an argument. Evidence is what an auditor actually reads.

**5:03**  The cryptographic bill of materials is generated from the scans themselves, in CycloneDX 1.6.

**5:12**  Every protocol, certificate and algorithm found, each with its quantum status.

**5:20**  Eighty-seven components in this estate. Two of them are already post-quantum.

**5:27**  Downloadable as JSON or CSV, so it can leave the product and still mean something.

**5:35**  Then the mapping to control frameworks. It is honest: this estate scores badly, and it says so.

**5:44**  Evidence packs collect the control artefacts with timestamps and a hash chain.


## 5. Action

**5:54**  Action.

**5:58**  Finding cryptography is the easy part. Changing it is the work.

**6:06**  Every fix moves through suggested, approved, pull request, and verified closed.

**6:14**  Two are closed and verified against a later scan. Seven are still open.

**6:22**  Open one and it carries the file, the current configuration, and the proposed change.

**6:30**  Approve, reject, validate, open a pull request, mark merged — every step is recorded against the asset.

**6:40**  Before you change a certificate authority, you want to know what depends on it.

**6:48**  Blast radius: assets, repositories and fixes in one graph you can interrogate.

**6:55**  Two roots and two issuing authorities sit under thirty-eight leaf certificates here.

**7:04**  If that public root failed, fifty-five dependent nodes would be affected, and the model prices it.

**7:14**  And a tripwire ladder: five canary keys at five strengths. Each only breaks if that algorithm breaks.

**7:24**  So the first one to trip tells you how far quantum capability has actually reached.


## 6. Governance

**7:33**  Governance.

**7:37**  For the board, one composite score — with every weight shown.

**7:44**  Inventory coverage, open exposure reduction, crypto-agility, blocker control.

**7:52**  Components with no evidence behind them are marked not measured, rather than scored from nothing.

**8:02**  Regulatory exposure is listed by regime, with the alignment state the evidence supports.

**8:12**  The executive view is the same view the engineers work in. There is no second set of numbers.


## 7. For the buyer's security team

**8:23**  If you are the security team buying this, four things matter.

**8:29**  One: tenant isolation is enforced in the database, not only in application code.

**8:37**  Row-level security, scoped per organisation, with a cross-tenant probe you can run yourself.

**8:46**  Two: vendor support cannot look at your workspace silently. Read-only, time-limited, with a stated reason.

**8:56**  Three: the audit trail is hash-chained, so a removed entry is detectable.

**9:04**  Four: the operators who run the platform sign in through an identity provider, with authenticator MFA.

**9:13**  Destructive actions ask for a fresh code. The shared key is an emergency credential only.

**9:22**  And the data boundary is explicit about what is allowed to leave your environment.

**9:30**  Cryptographic metadata, fingerprints and workflow records may cross. Source code, private keys and tokens do not.
