# CAM/API Transparent Proxy Deployment

The Automated CAM/API package is generated by:

`POST /crypto-mesh/middleware-plan`

It produces a deployable reverse-proxy and sidecar package for quantum-safe traffic wrapping with
zero application code changes after the customer routes traffic through the gateway or injects the
sidecar.

## What It Does

- Inbound: the CAM ingress gateway accepts TLS 1.3 with the requested hybrid/PQC group when the
  Envoy runtime supports it, then forwards raw TCP to the original upstream.
- Outbound: the CAM egress sidecar uses Linux `iptables` redirection to capture selected TCP flows
  and wrap them in a TLS tunnel to the CAM ingress gateway.
- Telemetry: the included Python agent submits runtime handshake proof to
  `/runtime-handshake/proof` without packet bodies, source code, private keys, or payload samples.
- Rollback: `transparent-egress-disable.sh` removes the NAT chain without touching application
  containers.

## What The Customer Must Still Do

- Deploy the CAM ingress gateway close to protected upstream services.
- Inject the egress sidecar into the workload pod/container namespace, or run CAM as a node/egress
  gateway.
- Provide destination CIDRs for safe traffic capture, or explicitly enable port-only capture for
  dedicated service ports.
- Provide production certificates from the customer internal CA.
- Use an OQS-enabled Envoy/OpenSSL/BoringSSL build when the selected hybrid group, such as
  `X25519MLKEM768`, must be negotiated end to end.

This is still no application code change. It is not zero infrastructure change.

## API Example

```powershell
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8001/crypto-mesh/middleware-plan" `
  -Headers @{"x-user-role"="operator";"x-user-id"="operator";"x-org-id"="org-alpha"} `
  -ContentType "application/json" `
  -Body '{
    "name": "pqc-agility-middleware",
    "deployment_mode": "transparent_sidecar",
    "emergency_algorithm": "X25519MLKEM768",
    "outbound_capture_port": 15001,
    "services": [{
      "name": "payments-api",
      "upstream_host": "payments-upstream",
      "upstream_port": 8443,
      "listen_port": 15443,
      "gateway_host": "payments-pqc-gateway",
      "destination_cidr": "10.42.10.15/32"
    }]
  }'
```

## Production Guardrails

- Start in `observe` or `shadow`; move to `enforce` only after handshake proof and customer
  rollback approval.
- Do not use broad port-only capture for shared ports like `443` unless the workload namespace is
  isolated.
- Certificate pinning and app-layer encryption are not solved by a network proxy. Use the platform's
  CI/CD buzzer and remediation workflow for those cases.
- The platform never needs customer packet payloads to prove CAM operation.
