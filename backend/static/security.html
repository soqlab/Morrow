Security Boundary

Minimum access by design.

The enterprise path is built around Quantum Airlock and minimum customer access: signed, redacted cryptographic evidence leaves the customer boundary; source code, private keys, secrets, and packet payloads do not leave by default.

Status

Controlled enterprise pilot / private beta. Production use still requires JWT auth, managed secrets, managed Postgres/Redis, RLS verification, backup evidence, and a passing go-live gate.

What Leaves

Evidence

Algorithm family, cipher suite, TLS version, certificate metadata, package hash, firmware hash, CI findings, runtime crypto metadata, and policy results.

Fingerprints

Salted host, repository, component, service, and device fingerprints when the customer chooses privacy-preserving mode.

Workflow

Ownership metadata, remediation state, validation result, audit events, and compliance ledger references.

What Never Leaves By Default

Code

No source-code upload is required for the Airlock-first workflow.

Secrets

No private keys, tokens, passwords, PEM keys, or cloud credentials should be submitted.

Payloads

No raw packet payloads, customer records, production data samples, or broad filesystem images are required.

Production Controls

Header auth is local/dev only. Production must use hosted JWT identity, least-privilege secret management, managed Postgres, managed Redis, and verified row-level security.

Identity

Use PQC_AUTH_MODE=jwt, PQC_AUTH_REQUIRED=1, real issuer/audience/JWKS, and MFA in the identity provider.

Airlock

Set PQC_AIRLOCK_SIGNING_KEY and PQC_AIRLOCK_REQUIRE_AGENT_SIGNATURE=1 for enterprise pilots.

Evidence

Archive go-live gate, launch collateral check, backup/restore, browser smoke, tenant isolation, and Trust Passport outputs.
